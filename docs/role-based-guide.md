# 按角色使用说明

这份文档不讲技术实现，专门讲“谁怎么用”。适合做内部培训、上线通知、使用手册。

## 1. 普通用户（`USER`）

### 1.1 这个角色主要做什么

普通用户的核心目标是两件事：

- 找到适合当前工作的工具和工作流
- 把自己验证过的工具和方法补充进系统

### 1.2 登录后常用页面

- `工具目录`
- `提交工具`
- `我的收藏`
- `工作流`

### 1.3 常见使用路径

#### 场景 A：我想找一个能解决问题的工具

1. 登录系统。
2. 进入“工具目录”。
3. 通过关键词搜索工具名称、摘要或描述。
4. 按标签筛选，或者按时间 / 热度排序。
5. 打开工具详情页查看：
   - 工具描述
   - 使用方法
   - 推荐人
   - 当前互动数据
6. 如果觉得有价值，可以点赞或收藏。

#### 场景 B：我想知道这个工具怎么用

1. 在工具详情页查看“工具描述”和“使用方法”。
2. 阅读评论区，了解其他同事的使用心得、限制条件和注意事项。
3. 如果链接可用，可以直接打开工具官网或工具入口。

#### 场景 C：我想把一个新工具推荐给团队

1. 进入“提交内容”页面。
2. 选择“提交工具”。
3. 填写：
   - 工具名称
   - 一句话摘要
   - 工具描述
   - 标签
   - 工具链接
   - 使用方法
4. 提交后等待审核，或在审核关闭时直接发布。

#### 场景 D：我的工具被驳回了

1. 进入工具详情页查看“提交记录”。
2. 阅读驳回备注。
3. 选择“修改后重新提交”，修正文案、链接或使用说明。
4. 如果不再需要这条记录，也可以直接删除这个已驳回工具。

#### 场景 E：我想把多个工具整理成一套方法

1. 进入“提交内容”页面。
2. 切换到“提交工作流”。
3. 填写工作流名称、适用场景、描述和步骤说明。
4. 按实际使用顺序选择关联工具。
5. 提交后进入审核流程。

### 1.4 普通用户的注意事项

- 提交工具时，工具链接必须是合法的 `http` 或 `https` 地址。
- 工具名称和链接不能与已有记录重复。
- 工作流必须至少关联一个已存在的工具。
- 评论区更适合写使用反馈、注意事项和推荐理由，不建议写纯情绪化内容。

## 2. 审核员（`REVIEWER`）

### 2.1 这个角色主要做什么

审核员的职责是把好内容质量关，确保平台上的工具和工作流：

- 信息完整
- 链接可访问
- 说明清晰
- 场景合理

### 2.2 登录后常用页面

- `审核中心`

### 2.3 常见使用路径

#### 场景 A：处理待审核工具

1. 登录后进入“审核中心”。
2. 选择“工具审核”标签页。
3. 将状态筛选为“待审核”。
4. 逐条查看：
   - 工具名称
   - 摘要
   - 标签
   - 提交人
   - 提交时间
5. 点“通过”或“驳回”。
6. 如果驳回，填写明确原因，便于提交人修改。

#### 场景 B：处理待审核工作流

1. 切换到“工作流审核”标签页。
2. 查看场景、描述、步骤和关联工具是否合理。
3. 点“通过”或“驳回”。
4. 驳回时说明问题，例如步骤不清晰、工具关联不合理、描述不足等。

### 2.4 审核建议

- 优先判断信息是否真实、可用，而不是只看格式是否好看。
- 驳回理由尽量具体，方便提交人一次改对。
- 对描述较弱但价值明显的内容，可以给出可执行修改建议。

### 2.5 审核员权限边界

审核员可以：

- 查看审核列表
- 通过审核
- 驳回审核
- 查看当前工具审核开关状态

审核员不可以：

- 新增或删除账号
- 修改角色权限
- 管理标签
- 管理导入导出
- 查看后台日志管理页
- 修改工具审核开关

## 3. 系统管理员（`ADMIN`）

### 3.1 这个角色主要做什么

管理员是平台的治理角色，负责：

- 账号与权限管理
- 标签治理
- 工具和工作流主数据维护
- 审核流程配置
- 导入导出
- 日志审计

### 3.2 登录后常用页面

- `工具管理`
- `标签管理`
- `审核中心`
- `账号权限`
- `导入导出`
- `日志审计`

### 3.3 常见使用路径

#### 场景 A：新增员工账号

1. 进入“账号权限”。
2. 点击“新增账号”。
3. 填写用户名、真实姓名、初始密码、状态和角色。
4. 保存后，将账号发给对应同事。

说明：

- 选择 `ADMIN` 后会自动视为管理员账号。
- 管理员账号的权限是固定全开，不做细粒度组合。

#### 场景 B：维护标签体系

1. 进入“标签管理”。
2. 新增、修改或删除标签。
3. 保持标签语义稳定，避免重复命名。

#### 场景 C：直接维护工具和工作流

1. 在“工具管理”中可以直接新增、编辑、删除工具。
2. 在“工作流管理”中可以直接新增、编辑、删除工作流。
3. 适合处理平台主数据修正、存量补录或集中治理。

#### 场景 D：调整审核策略

1. 进入“审核中心”。
2. 查看“工具审核开关”。
3. 决定当前阶段是否启用人工审核：
   - 开启：新工具进入待审核
   - 关闭：新工具自动通过

当前版本说明：

- 工具审核开关已在前端管理台开放。
- 工作流审核仍按系统配置执行，默认开启。

#### 场景 E：批量导入历史工具

1. 进入“导入导出”。
2. 下载导入模板。
3. 整理 CSV 内容。
4. 先做“预校验”。
5. 校验通过后执行“正式导入”。
6. 检查导入任务结果和失败明细。

#### 场景 F：导出数据盘点

1. 进入“导入导出”。
2. 选择要导出的字段。
3. 生成导出文件。
4. 用于盘点、复核、归档或给其他系统对接。

#### 场景 G：追踪关键操作

1. 进入“日志审计”。
2. 分别查看：
   - 审计日志
   - 操作日志
3. 按动作、模块、成功状态、操作者等条件过滤。

### 3.4 管理员日常建议

- 首次上线后立即修改默认管理员密码。
- 先规划标签体系，再开放大规模提交，能明显减少后续清洗成本。
- 每次版本升级前先备份数据库。
- 对“审核通过率低”的提交内容，建议做一次填写规范培训。

## 4. 适合怎么做内部培训

如果这套系统要在公司内部推广，建议培训顺序如下：

1. 先给普通用户讲“如何找工具、如何提交工具、如何查看驳回原因”。
2. 再给审核员讲“审核标准和驳回备注写法”。
3. 最后给管理员讲“账号、标签、批量导入、日志和审核开关”。

这样最容易让大家形成统一理解，也最适合做分角色培训材料。

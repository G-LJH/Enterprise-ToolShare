# 项目概览

## 1. 项目定位

企具共享（Tool Share）是一个面向公司内部使用的工具资产管理平台。它不是单纯的“工具链接收集站”，而是把以下几类内容放进同一套系统：

- 工具目录
- 使用说明
- 标签分类
- 提交审核
- 点赞收藏评论
- 工作流沉淀
- 审计与治理

它适合用来解决这几类常见问题：

- 团队都在用工具，但缺少统一入口，新人不知道去哪里找。
- 同一类工具被反复调研、反复试用，经验无法沉淀。
- 工具推荐缺少审核与责任人，容易出现失效链接、内容质量不稳定的问题。
- 管理者想知道哪些工具被高频使用、哪些提交需要审核、谁做过哪些关键操作。

## 2. 核心能力

### 2.1 工具目录

系统支持把企业内外部常用工具沉淀为标准记录，包含：

- 工具名称
- 一句话摘要
- 工具描述
- 工具链接
- 使用方法
- 标签
- 推荐人
- 点赞、收藏、评论统计
- 审核状态

普通用户可以浏览、搜索、筛选、收藏和点赞；管理员可以直接新增、编辑、删除工具。

### 2.2 工具提交与审核

普通用户可以提交新工具。提交后系统会根据审核开关决定走哪条路径：

1. 审核开启：工具进入“待审核”，由审核员或管理员处理。
2. 审核关闭：工具自动通过并进入可见列表。

如果工具被驳回：

- 提交人可以查看驳回备注
- 可以修改后重新提交
- 也可以直接删除该驳回工具

### 2.3 工作流沉淀

除了单个工具，系统还支持提交“工作流”。

工作流适合沉淀一套完整做法，例如：

- 行业调研工作流
- 内容策划工作流
- PPT 制作工作流
- 新品分析工作流

每个工作流可以配置：

- 工作流名称
- 适用场景
- 描述
- 步骤说明
- 关联工具及顺序
- 是否精选

这样团队不只是知道“能用什么工具”，还知道“这些工具应该怎么组合使用”。

### 2.4 协作反馈

系统当前提供这些互动能力：

- 工具点赞
- 工具收藏
- 工具评论
- 工作流点赞
- 工作流收藏

这些数据可以帮助团队识别高价值内容，也能帮助管理员发现真正常用的工具和流程。

### 2.5 标签与搜索

管理员可以统一维护标签池，普通用户在提交时可以复用标签。

系统支持：

- 关键词搜索
- 按标签筛选
- 按时间排序
- 按热度排序
- 按场景筛选工作流

这让工具目录更接近“可治理的知识库”，而不是简单列表。

### 2.6 账号、权限与治理

系统内置三类角色：

- `USER`
- `REVIEWER`
- `ADMIN`

管理员可以在后台完成：

- 新增账号
- 编辑账号
- 启停账号
- 重置密码
- 分配角色

系统启动时会自动创建默认管理员账号，用于首次初始化。

### 2.7 审计与日志

系统会记录关键管理动作，例如：

- 登录成功 / 登录失败
- 工具创建、修改、删除
- 工具审核通过 / 驳回
- 工作流审核通过 / 驳回
- 导入导出任务
- 系统配置修改

后台还提供操作日志与审计日志页面，方便管理员追溯问题和核对责任。

### 2.8 批量导入导出

管理员可以用 CSV 批量维护工具数据：

- 下载导入模板
- 上传 CSV 进行预校验
- 执行正式导入
- 按字段导出工具数据
- 查看导入导出任务记录

这对“已有大量存量工具，需要一次性入库”的场景很有用。

## 3. 三类身份与权限边界

| 身份 | 主要目标 | 典型操作 | 页面范围 |
| --- | --- | --- | --- |
| 普通用户 | 找工具、用工具、提交内容 | 搜索、查看详情、点赞、收藏、评论、提交工具、提交工作流、查看自己的驳回记录 | 工具目录、提交页、收藏页、工作流页 |
| 审核员 | 控制内容质量 | 查看待审核工具/工作流、通过、驳回、填写审核备注 | 审核中心 |
| 系统管理员 | 维护系统和数据治理 | 审核、账号权限、标签管理、工具管理、工作流管理、导入导出、日志审计 | 全部页面 |

补充说明：

- 审核员可以进入审核中心，但不能管理账号、标签、日志和导入导出。
- 管理员拥有全量管理能力，同时也可以参与审核。
- 工具审核开关可由管理员在管理台修改。
- 工作流审核当前默认开启，后端有配置项支持，现版本前端未单独提供开关入口。

## 4. 关键业务流程

### 4.1 工具从提交到上线

1. 普通用户提交工具。
2. 系统校验名称、链接、描述、使用方法和标签是否合法。
3. 如果审核开启，状态进入 `PENDING_REVIEW`；否则直接 `APPROVED`。
4. 审核员或管理员在审核中心处理：
   - 通过：工具进入 `APPROVED`
   - 驳回：工具进入 `REJECTED`
5. 提交人可查看审核备注。
6. 驳回后，提交人可以修改重提，或删除该工具。

### 4.2 工作流从提交到复用

1. 普通用户在提交页选择“提交工作流”。
2. 填写场景、步骤并关联至少一个工具。
3. 工作流进入审核流程。
4. 审核通过后，其他用户即可在工作流目录中查看、点赞、收藏和复用。

### 4.3 管理治理闭环

管理员可以围绕内容治理做完整闭环：

1. 创建账号并分配角色
2. 维护标签体系
3. 管理工具与工作流主数据
4. 处理审核积压
5. 批量导入历史数据
6. 导出数据做盘点
7. 通过日志追踪关键操作

## 5. 状态说明

### 5.1 工具状态

| 状态 | 含义 |
| --- | --- |
| `DRAFT` | 保留状态，当前主流程中基本不直接面向用户使用 |
| `PENDING_REVIEW` | 已提交，等待审核 |
| `APPROVED` | 已审核通过，可正常展示 |
| `REJECTED` | 已驳回，提交人可修改重提 |
| `OFFLINE` | 下线状态，不对普通浏览展示 |

### 5.2 审核单状态

| 状态 | 含义 |
| --- | --- |
| `PENDING` | 待审核 |
| `APPROVED` | 已通过 |
| `REJECTED` | 已驳回 |

## 6. 技术架构简述

系统采用前后端分离结构：

- 前端：Next.js + TypeScript + Ant Design
- 后端：Spring Boot + Java 21
- 数据库：PostgreSQL 16
- 数据迁移：Flyway
- 部署：Docker Compose

部署上主要有三种方式：

1. 本机开发模式
2. Docker Compose 标准部署
3. 基于 Docker 的公司内网服务器部署

详细步骤见 [部署运维说明](deployment-guide.md)。

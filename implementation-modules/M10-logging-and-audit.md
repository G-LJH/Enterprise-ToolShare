# M10 日志与审计

状态：`done`

## 1. 模块目标

实现系统日志、业务日志、审计日志的统一方案，并保证关键操作可追溯。

## 2. 实现范围

- 日志分类方案
- 管理员操作审计
- 导入导出日志
- 登录日志
- 错误日志规范

## 3. 非范围

- 不做复杂告警平台接入

## 4. 前置依赖

- `M00`
- `M01`
- 部分业务模块已具备关键操作

## 5. 数据设计

涉及表：

- `audit_logs`
- `operation_logs`

建议字段：

- 操作者
- 模块
- 操作类型
- 对象类型
- 对象 ID
- 结果
- 时间
- 数据摘要

## 6. 接口设计

- 审计日志列表
- 操作日志列表

## 7. 页面或交互影响

- 管理端日志管理页

## 8. 实现步骤

1. 定义日志模型和埋点规范
2. 在关键管理员操作增加审计记录
3. 在错误链路中标准化错误日志
4. 实现日志查询页

## 9. 风险点

- 日志字段不统一导致无法排查
- 日志记录过少或过多

## 10. 测试方案

### 单元测试

- 日志组装逻辑

### 集成测试

- 管理员操作是否落审计日志
- 错误是否进入错误日志

### 接口测试

- 日志查询接口可分页筛选

### 页面验证

- 日志页可查询和筛选

### 安全验证

- 日志中不泄露密码和敏感明文

## 11. 验收标准

- 关键操作可追溯
- 日志分类清晰
- 查询能力可用

## 12. 当前实现说明

### 实现范围

- 已保留并统一收口各业务模块已有的 `audit_logs` 关键审计记录
- 已新增统一 `operation_logs` 记录，用于覆盖登录行为和管理端写操作结果
- 已补齐异常链路日志规范，业务异常记录 `warn`，未知异常记录 `error`
- 已实现管理端日志页，可分别查询审计日志和操作日志

### 数据与接口设计

- 数据库迁移文件为 `backend/src/main/resources/db/migration/V9__m10_logging_and_audit.sql`
- 本次对 `audit_logs` 与 `operation_logs` 增加了查询索引，保障日志筛选性能
- 管理侧接口为：
  - `GET /api/admin/logs/audit`
  - `GET /api/admin/logs/operations`
- 两类接口均支持 `page`、`size` 分页参数
- 审计日志支持按 `action`、`objectType`、`keyword` 查询
- 操作日志支持按 `module`、`success`、`keyword` 查询

### 测试方案

- 日志接口与行为验证：`AdminLogControllerTests`
- 后端全量验证：`cd backend && mvn test`
- 前端校验：`cd frontend && npm run lint && npm run build`

### 验收结论

- 管理员关键操作现在同时具备对象级审计记录与结果级操作日志
- 登录成功、失败、登出均可追踪，便于账号与安全排查
- 管理员可分页查询审计日志和操作日志，形成最小可验证闭环
- `M10` 已满足 `M11` 集成联调前的日志与审计基础能力
